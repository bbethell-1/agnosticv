== OpenShift 4 Disconnected Workshop
Welcome to the OpenShift 4 Disconnected Workshop! In this workshop you'll learn to prepare for, install and operate an OpenShift cluster in a disconnected network.
A disconnected network, also known as an airgap'd network, is an environment where the servers don't have access to the Internet (not even through a proxy or firewall).
Preparing for a disconnected cluster requires the administrator to mirror the installation container images and any additional Operators.
Examples of additional Operators include the Web Terminal, Cluster Logging, Virtualization, Security & Management, Storage and GitOps.
The mirrored content should be refreshed periodically in order to apply security patches, new features, and resolve bugs.

== Workshop Architecture
This workshop creates a few resources in an Amazon AWS environment to accompany the Lab Guide / Instructions.
You will be responsible for creating your own disconnected cluster.
The resources created for you are:

* A *jump* server that can download the installation container images from redhat.com, openshift.com, and quay.io
** The *jump* server lives in a subnet that allows access to those resources
* A *highside* server that will serve the installation content
** The *highside* server lives in a disconnected / airgap'd / private subnet
* A *nat* server that will allow the *highside* server to:
** Install RHEL RPMs from the AWS repos
** Create AWS instances for the OpenShfit cluster you will create
** The *nat* server uses a restricted Squid proxy to block the *highside* server from talking to any other internet resources
* A *salsa-registry* server which is a functioning example of the mirroring process and installing OpenShift
** Feel free to look at the *salsa-registry*'s /root/playbook.yaml to compare your work with a functional example

== Topics & Technologies discussed
These are the topics and technologies that you'll learn about in this workshop

* *oc-mirror* - A tool to help you download the OpenShift installation images, additional Operators, images, and Helm charts
* *mirror-registry* - A mini version of the Quay container image registry (like a web server for RPMS, but for container images)
* *oc* and *openshift-install* - The tools used to create/install an OpenShift cluster
