OpenShift Developer Namespace provides a dedicated namespace on a shared OpenShift cluster for building, testing, and deploying applications. Developers can use this self-service environment to deploy workloads, develop demo assets, or experiment with OpenShift capabilities without waiting for a full cluster to provision. No cluster-admin privileges are provided -- each namespace comes with its own credentials, resource quota, and optional OpenShift Virtualization support.

[WARNING]
====
This service is currently in beta. Features and resource quotas are subject to change.
====

[TIP]
====
All clusters are currently OpenShift 4.18. New versions of OpenShift will be released in the future.
====

== What You Get

* *OpenShift Namespace* -- A private space for your projects (sandbox-GUID-SUFFIX)
* *Service Account Credentials* -- Programmatic access to the OpenShift API
* *Console Credentials* -- Log into the OpenShift Web Console
* *OpenShift Virtualization* (optional) -- Run VMs in your namespace
* *MetalLB Operator* -- Provides external IPs for services
* *OpenShift GitOps (ArgoCD) Operator* -- GitOps workflows for application deployment

== Resource Quota

Your namespace comes with the following resources:

|===
| Resource | Limit

| *CPU*
| 10

| *Memory*
| 20 Gi

| *Storage*
| 100 Gi
|===

== Use Cases

* Develop and test demo assets before publishing to RHDP
* Prototype applications on OpenShift
* Explore OpenShift features as a playground
* Quick development without cluster provisioning wait times
