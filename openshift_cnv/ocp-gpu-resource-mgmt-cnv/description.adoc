Experience GPU-as-a-Service (GPUaaS) on OpenShift without physical GPU hardware. This hands-on workshop simulates GPU resources using a fake GPU device plugin, so you can learn GPU scheduling, booking, and workload management patterns at scale — without the cost or availability constraints of real accelerators.

You will work through the full GPUaaS lifecycle: reserve GPU time through a calendar booking interface, observe how reservations become Kueue queues and OpenShift AI Hardware Profiles, deploy workloads with guaranteed GPU access, and trigger preemption to see how reserved workloads take priority over unreserved ones.

== Lab Guide

A preview of the lab guide is available here: +
link:https://rhpds.github.io/gpu-resource-mgmt-showroom/modules/index.html[GPU Resource Management on OpenShift — Lab Guide^]

== This lab covers

- Simulating GPU hardware with the fake GPU operator — device plugin, nvidia-smi emulation, and MIG partitions
- Reserving GPU time through the GPU Booking App — an OpenShift Console plugin with a calendar interface
- Understanding how bookings create Kueue ClusterQueues, LocalQueues, and Cohorts behind the scenes
- Configuring RHOAI Hardware Profiles that connect GPU reservations to OpenShift AI workbenches
- Launching a workbench with guaranteed GPU access using a reserved Hardware Profile
- Testing multi-user GPU contention and observing Kueue preemption in action

== Featured Technology and Products

* Red Hat OpenShift Container Platform 4.21
* Kueue — Kubernetes-native batch workload manager
* Red Hat OpenShift AI
* OpenShift GitOps (ArgoCD)
* Fake GPU device plugin with switchable GPU profiles
* GPU Booking App (OpenShift Console plugin)
