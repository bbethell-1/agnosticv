Red Hat OpenShift Container Platform provides comprehensive observability through must-gather archives, Insights data, and OVN database exports that enable offline troubleshooting of complex cluster issues. This hands-on lab explores diagnostic tools including omc, etcd-ocp-diag.py, ocp_insights.py, and kubectl-dev_tool to systematically analyze cluster failures without requiring a running cluster. Learners work through real-world scenarios covering etcd performance, API overload, and OVN-Kubernetes network debugging using restored database snapshots and archived must-gather data.

== Detailed Overview

* *Tools of the Trade*
** Introduction to 8 community-created diagnostic tools for OpenShift troubleshooting
** Overview of omc (OpenShift Must-Gather Client), kubectl-dev_tool, yq, jq, etcd-ocp-diag.py, and ocp_insights.py
** Introduction to OVN debugging tools: ovnkube-trace, ovn-trace, and ovn-nbctl

* *Intro to omc*
** Deep dive into omc-specific commands beyond standard oc-like operations
** Inspect certificates, etcd health/status, haproxy backends, and machine-config differences
** Review node logs, OVN subnets, and Prometheus alertrules from must-gather archives

* *Using OpenShift Lightspeed (Insights) to Proactively Analyze a Cluster*
** Parse Insights archives to review cluster info, node status, and cluster operator health
** Analyze customer namespace memory usage and etcd slow apply metrics
** Review restarting containers, alerts, PodNetworkConnectivityChecks, and conditional update risks

* *Analyzing etcd Performance*
** Identify common etcd errors including "Apply Request Took Too Long" and "Leader is Overloaded"
** Use etcd-ocp-diag.py to calculate maximum latency, error counts, and timing patterns
** Drill down by date, pod, and error type to pinpoint performance issues

* *What is Overloading my API?*
** Analyze audit logs using kubectl-dev_tool audit to identify API overload causes
** Group and filter requests by resource, user, verb, and time range
** Investigate real-world case study of API overload caused by operator behavior

* *Debugging OVN-Kubernetes - The Setup*
** Configure the OVN offline debugging environment using restored database snapshots
** Understand the demo application architecture with pods, VMs, and secondary networks
** Review NetworkPolicies and MultiNetworkPolicies affecting the lab environment

* *OVN-Kubernetes - Pods Cannot Communicate in the Same Namespace*
** Trace pod-to-pod traffic using ovn-trace to identify blocked connections
** Inspect portgroups and ACLs to understand NetworkPolicy enforcement in OVN
** Resolve connectivity by creating appropriate NetworkPolicy to allow same-namespace traffic

* *OVN-Kubernetes - Cross-Namespace Communication Issues*
** Debug why some pods can communicate between namespaces while others fail
** Analyze portgroup membership to understand selective NetworkPolicy application
** Identify missing podSelector labels causing partial connectivity failures

* *OVN-Kubernetes - VirtualMachine External Access Issues*
** Trace VM traffic on secondary networks (localnet topology with VLANs)
** Debug MultiNetworkPolicy enforcement on OpenShift Virtualization workloads
** Understand localnet switch behavior and multicast flooding for external destinations
