== Platform Engineering Workshop on OpenShift 5

[WARNING]
====
Development only. This is the OpenShift 5 port tracked by GPTEINFRA-18224,
not a production-ready workshop. Deployment and operator compatibility
must be validated before scheduling an event.
====

Each deployment uses a dedicated, compact three-node OpenShift 5 cluster
from the CNV pool. Cluster-login authentication uses the original workshop's
htpasswd setup. The GitOps charts manage their own Keycloak and
adds the `developers` identity provider for workshop applications.

The OpenShift 5 development branch keeps the workshop sources together:

* https://github.com/rhpds/platform-engineering-workshop/tree/ocp5-update/automation/ansible[Workshop automation^]
* https://github.com/rhpds/platform-engineering-workshop/tree/ocp5-update/automation/gitops[GitOps infrastructure^]
* https://github.com/rhpds/platform-engineering-workshop/tree/ocp5-update/content[Showroom instructions^]

The development order form allows these source settings to be
overridden without changing the original workshop CI.

Model access is allocated through MaaSSandbox, with one shared virtual key
per dedicated environment and the existing four models. The workshop passes
one API URL/key pair into Vault for shared Dev Spaces access, not per-user
keys. Credentials retain the workshop's `litellm_*` user-data names; MaaS
manages the key lifecycle.

Participants act as platform engineers at Parasol Insurance, building an
Internal Developer Platform with OpenShift, GitOps, Vault, Red Hat Developer
Hub, self-service templates, and software supply chain security tooling.

The existing https://redhat-pe-workshop.github.io/showroom-roadshow-v2/modules/index.html[workshop preview^]
has not yet been adapted for OpenShift 5. Access details, credentials, and
URLs are provided through Showroom after deployment.

*Audience:* Platform Engineers, DevOps Leads, Development Team Leads, Technical Decision Makers
