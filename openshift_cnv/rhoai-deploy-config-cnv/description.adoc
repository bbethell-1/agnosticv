Deploy, configure, and operate Red Hat OpenShift AI on OpenShift Container Platform. This hands-on lab covers the full lifecycle from installation through model serving, governance, scaling, and observability — all using CPU-only inference to keep costs down.

== Featured Technology and Products

* Red Hat OpenShift AI 3.5
* OpenShift Container Platform
* Red Hat OpenShift GitOps (Argo CD)
* vLLM (CPU inference)
* llm-d (Distributed Inference)
* Models-as-a-Service (MaaS) with Red Hat Connectivity Link
* KEDA (Custom Metrics Autoscaler)

== Detailed Overview

* *Module 1: Install RHOAI (Connected)*
** Install the RHOAI Operator and wait for the CSV to reach Succeeded
** Create a DataScienceCluster enabling dashboard, KServe, and AI Gateway components
** Log into the RHOAI dashboard and confirm the predefined namespaces

* *[Optional/Reference] Module 2: Install RHOAI (Disconnected / Air-gapped)*
** Set up oc-mirror v2 and mirror RHOAI operator images to a tar archive
** Deploy a Quay mirror registry and push the archive using the disk-to-mirror workflow
** Apply a local CatalogSource and ImageDigestMirrorSet for offline operator installs
** Explore a Quay.io proxy pull-through cache as a lighter-weight alternative

* *Module 3: Model-Serving Platform*
** Enable KServe single-model serving cluster-wide (ModelMesh removed in 3.4+)
** Instantiate the pre-installed vLLM CPU (x86) ServingRuntime template into the project
** Model weights loaded from OCI modelcar images — no object storage required

* *Module 4: Serving with vLLM*
** Deploy Qwen2.5-0.5B-Instruct on CPU with token-authenticated external route
** Send authenticated inference requests to the OpenAI-compatible /v1/completions endpoint
** Compare the access-control spectrum: internal, external, token auth, and governed MaaS

* *Module 5: MaaS Governance*
** Enable Models-as-a-Service in the DataScienceCluster and provision the PostgreSQL backend
** Install Red Hat Connectivity Link, register Kuadrant, and bootstrap the MaaS gateway
** Publish a model as an LLMInferenceService with MaaSModelRef, subscription, and auth policy
** Mint API keys, enforce per-subscription token rate limits, and observe usage telemetry
** Monitor inference traffic in the Observability dashboard (Prometheus, Thanos, Perses)

* *Module 5a: External Models*
** Deploy the llm-katan echo simulator covering five provider types (OpenAI, Anthropic, Azure OpenAI, Bedrock, Vertex AI)
** Publish simulator models through the MaaS gateway using ExternalModel and ExternalProvider CRDs
** Call each provider with a governed API key and view metrics in the Observability dashboard

* *Module 6: Scaling with llm-d + KEDA*
** Install the Custom Metrics Autoscaler (KEDA) and deploy a model as an LLMInferenceService
** Publish the scaling model through MaaS with a high-limit subscription for load testing
** Scale replicas automatically on vLLM queue depth (num_requests_waiting) via a KEDA ScaledObject
** Drive sustained concurrent load and correlate scaling events with queue-depth and token telemetry
