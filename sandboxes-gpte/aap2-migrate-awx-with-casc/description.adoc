Use Configuration as Code to migrate from AWX or Ansible Tower to Ansible Automation Platform. This workshop will show how to migrate the configuration of AWX, Ansible Tower or Ansible Automation Platform (1.0 - 2.3), to a new instance of Ansible Automation Platform (2.4). The process is not 100% automatic, but avoids the needs of the official upgrade processes and introduces to a new way to manage the AAP the configuration. Once the migration is complete, this initial configuration can be used to effectively manage the AAP instance using GitOps, as described at the workshop https://demo.redhat.com/catalog?item=babylon-catalog-prod/ansiblebu.aap2-workshop-casc.prod&utm_source=webapp&utm_medium=share-link[Automation Controller configuration Continuous Deployment with CasC^].

=== Specifications

* One AWX 11.2.0 instance (containerized) on RHEL 9
* One Automation Controller on RHEL 9

=== Supporting Materials

*Access guide:* After you complete provisioning, you receive an email with a website containing a user credential and access to the following: AWX web UI Automation Controller web UI Visual Studio Code (including a terminal) for AWX Visual Studio Code (including a terminal) for Automation Controller Backup direct SSH access The website provided with this information is dynamically created upon provisioning. The web address is your four-digit unique identification number plus the GPTE DNS "open.redhat.com" or something similar, for example: http://87f8.open.redhat.com/
