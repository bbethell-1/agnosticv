In this lab, you will build an intelligent, self-healing automation workflow using:

*Red Hat AI* for understanding service issues

*Ansible Lightspeed* to generate remediation playbooks

*Ansible Automation Platform (AAP)* workflows for orchestration

*Event-Driven Ansible (EDA)* to listen to real-time service events

The goal is to showcase how automation + AI can be used to detect, analyze, and remediate application failures *without writing any playbooks manually*.

=== About AIOps
AIOps (Artificial Intelligence for IT Operations) combines three key components:

* *Observability* - Understanding system state through logs, metrics, and traces
* *Inference* - Using AI to analyze and predict based on data  
* *Automation* - Automatically detecting, responding to, and resolving IT issues

This lab demonstrates how Red Hat technologies work together to create self-healing infrastructure that can incrementally adopt AIOps principles.

=== Lab Environment
The workshop environment includes:

* RHEL node with Apache (httpd) service
* Filebeat for log monitoring
* Kafka for event streaming
* Event-Driven Ansible for real-time response
* Red Hat AI and Ansible Lightspeed for intelligent automation
* Gitea for source control
* Mattermost for notifications

Once provisioned, you'll be logged in as `lab-user` with all content preconfigured and ready to run.

=== Workshop Agenda
This hands-on lab consists of four main parts:

. *Event-Driven Ansible Response* - Automatic detection of systemd application outages
. *Log Enrichment and Prompt Generation* - AI-powered incident analysis and notification
. *Remediation Workflow* - Automated playbook generation using Ansible Lightspeed
. *Execute HTTPD Remediation* - Actual resolution of the application outage

NOTE: These workflows are intentionally separated to allow human review and course correction at natural breakpoints, enabling incremental AIOps adoption.
