Use custom security content to automate security compliance with custom security policies.

This catalog item explains how to implement custom security content for automated security compliance not only with industry-standard security standards, such as DISA STIG and PCI-DSS, but also with an organization's specific custom security policies.

This item describes how to:

  • Use the OpenSCAP scanner to scan systems and perform security fixes as needed.
  • Navigate among existing rules and modify them and take advantage of parameterization.
  • Create new security profiles and populate them with existing rules.
  • Create new rules from scratch and add them to security profiles.
  • Write Open Vulnerability and Assessment Language (OVAL) checks with minimal effort and ensure correctness.
  • Create Red Hat Ansible Automation Platform content for system remediations.

Audience: System administrators, cloud administrators and operators, architects, and others working on infrastructure operations management who are interested in learning how to automate security compliance

Product(s): Red Hat Enterprise Linux

Specifications

  • One controller t2.medium (Red Hat Enterprise Linux 8 virtual machine with GUI environment)
  • Default environment lifespan: Two days (extensions available)
  • Default environment runtime: Six hours (extensions available)

Prerequisites: Basic Linux skills gained from Red Hat® Certified System Administrator (RHCSA) certification or equivalent system administration skills

Provisioning time: Typically, approximately one hour
