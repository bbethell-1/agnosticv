Provides an OpenShift cluster with OpenShift GitOps installed and optional LiteMaaS/MaaS integration for AI/LLM demos.
You must provide the URL to your GitOps repo that has all of the code you need in order to deploy your demo or workshop environment.

You can write your automation using native OpenShift/Kubernetes manifests or Ansible, which will be run via a GitOps configured job on your OpenShift cluster.

[NOTE]
====
The GitOps controlled deployment is not monitored or verified by the RHDP platform.
You have control (and responsibility) over exactly what is deployed to the cluster.
====

== Instructions

You will receive an OpenShift cluster with the selected number of nodes (SNO or multi-node) that you specify. Only an authenication provider (RHBK), OpenShift Lightspeed, and OpenShift GitOps will be installed and configured in the cluster.

* Everything else is defined by you and is deployed by OpenShift GitOps. If you want to know how this works, you can find our link:https://github.com/rhpds/core_workloads/tree/main/roles/ocp4_workload_field_content[GitOps Bootstrap role^] in the Agnosticd v2 core workloads repository.
* There are two examples in the template repo. Both are deployed as Helm charts using OpenShift GitOps.
** The `examples/helm` path deploys an App of Apps with each component optionally enabled or disabled. Each of the apps or components are defined in the `components` folder.
** The `examples/ansible` path deploys several components, the most important being the Ansible Runner job. This will run the playbook (and associated roles) that you define.
** All (or most) values & vars should be controlled through the `values.yaml` file that is used by the Helm chart.

To get started, you have the option of cloning the template link:https://github.com/rhpds/field-sourced-content-template.git[Field Sourced Assets^] repo and making changes or adding your code and configuration. If you do not want to use this template repo and want to start with your own, just make sure that you have a Helm chart in the GitOps Path you provide when ordering.

=== LiteMaaS/MaaS Integration (Optional)

For AI/LLM demos, you can enable LiteMaaS API key provisioning when ordering. This will:

* Automatically provision a temporary virtual API key for a selected LLM model
* Inject the credentials into your Helm chart values as `litemaas.apiUrl`, `litemaas.apiKey`, and `litemaas.model`
* Support configurable key duration (3, 7, 10, or 30 days)

To use LiteMaaS, check the *Enable LiteMaaS/MaaS API Keys* checkbox when ordering and select your preferred model from the dropdown.
