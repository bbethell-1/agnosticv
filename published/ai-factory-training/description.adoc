= AI Factory Training

== Overview

Customer-facing training environment for AI Factory topics, designed for Product Training and Learning (PTL) delivery.

This catalog item provides OpenShift AI 3.4 environments for building and deploying enterprise AI applications. Choose between **CPU-only (CNV)** or **GPU-accelerated (AWS)** infrastructure based on your training module requirements.

== Cloud Provider Options

=== CNV (CPU-Only) - Default

*Use for*: Basic AI Factory concepts, UI exploration, and lessons that don't require GPU

* **Cost**: Low
* **Performance**: CPU-based inference (slower)
* **Provisioning**: Fast (minutes)
* **MaaS Integration**: Includes LiteLLM virtual API keys for model inference
* **Best For**: Phases 1 & 2 of AI Factory training

=== AWS (GPU-Enabled)

*Use for*: GPU-specific lessons on configuration, slicing, and optimization

* **Cost**: High (GPU instance charges apply)
* **Performance**: Fast GPU-accelerated inference
* **Provisioning**: Extended (GPU availability limited)
* **GPU**: NVIDIA L4 (24GB VRAM)
* **Best For**: Phase 3 of AI Factory training

== Training Curriculum Support

This environment supports comprehensive AI Factory training including:

=== All Providers (CNV & AWS)

* Building and deploying AI agents
* Retrieval-Augmented Generation (RAG)
* AI development tools and workbenches
* Model management with KServe
* AI safety and reliability

=== GPU-Specific Topics (AWS Only)

* GPU configuration and operator setup
* GPU slicing (MIG and time-slicing)
* GPU monitoring and performance metrics
* GPU resource management
* GPU-accelerated model training
* Performance optimization for production

== OpenShift AI 3.4 Platform

Both environments include Red Hat OpenShift AI 3.4 with:

* **Data Science Pipelines** - Build and orchestrate ML workflows
* **KServe** - Model serving with GPU support (AWS)
* **Model Registry** - Track and version AI models
* **Ray** - Distributed computing
* **TrustyAI** - Model monitoring and observability
* **Training Operator** - Distributed training
* **Workbenches** - Jupyter notebooks for development
* **Feast** - Feature store
* **Llama Stack Operator** - AI agent infrastructure
* **AI Pipelines** - End-to-end ML pipelines

== Environment Features

=== CNV Environment

* Single Node OpenShift on CNV infrastructure
* Keycloak authentication
* **MaaS Integration**: Virtual API keys for AI model inference
  ** Models: granite-4-0-h-tiny, qwen3-14b
  ** Duration: 3 days
* OpenShift Lightspeed for AI assistance
* Low-cost, fast provisioning

=== AWS Environment

* Single Node OpenShift on g6.8xlarge (NVIDIA L4 GPU)
* Keycloak authentication
* **GPU Operator v25.3** with monitoring dashboard
* **Node Feature Discovery** for automatic GPU detection
* **Certificate Manager** with AWS Route53 integration
* Production-like GPU performance

== Important Considerations

=== CNV (CPU-Only)

✅ **Advantages**:
* Low cost
* Fast provisioning
* MaaS for real inference
* Suitable for most training content

⚠️ **Limitations**:
* Slower CPU-based inference for local models
* Not suitable for GPU-specific lessons

=== AWS (GPU-Enabled)

✅ **Advantages**:
* Real GPU acceleration
* Production-like performance
* Ideal for GPU training modules

⚠️ **Limitations**:
* **High cost** - GPU instances are expensive
* **Long provisioning** - Can take significantly longer
* **Limited availability** - GPU resources not guaranteed
* **Chargeback** - Costs charged to your organization
* **No MaaS** - Uses real GPU instead

[IMPORTANT]
====
**GPU Cost Management**:

* Only order AWS (GPU) for GPU-specific training lessons
* Use CNV for all non-GPU content
* Stop or destroy GPU environments immediately after use
* Coordinate with your training instructor
* Monitor your organization's GPU usage

The learning platform manages which version to provision based on lesson requirements.
====

== When to Choose Each Option

=== Choose CNV (Default)

* UI exploration and basic functionality
* Model inference using MaaS
* Non-GPU training content
* Cost-sensitive environments
* Quick provisioning needed

=== Choose AWS (GPU)

* GPU configuration and setup
* GPU slicing and resource management
* GPU monitoring and observability
* GPU-accelerated model training
* Performance optimization with GPUs
* Only when GPU capabilities are required for the lesson

== Getting Started

1. **Select Cloud Provider**: Choose CNV (default) or AWS based on your training module
2. **AWS Only**: Select GPU instance type and region
3. Order the environment through RHDP
4. Access OpenShift console and OpenShift AI dashboard
5. Follow your training materials
