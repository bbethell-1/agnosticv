Use Configuration as Code to maintain all aspects of Red Hat Ansible Automation Platform.

This catalog item provides code to demonstrate how to use Configuration as Code (CasC) to maintain all aspects of Ansible Automation Platform. The provided code is a starting point, and the asset guides you through how to utilize the code and make it your own. This asset covers configuring the automation controller, private automation hub, execution environments, and custom collections as well as creating workflows without the GUI as an example to follow along. These principles help prevent drift in configuration, allow changes to require approval before implementation, and help maintain both a development and production deployment.

Access guide: After you complete provisioning, you receive an email with a website containing a user credential and access to the following:

  • Automation controller web UI
  • Visual Studio Code (including a terminal)
  • Backup direct SSH access

The website provided with this information is dynamically created upon provisioning. The web address is your four-digit unique identification number plus the GPTE DNS "open.redhat.com" or something similar--for example: http://87f8.open.redhat.com/
