Welcome to the Workshop/Demo to configure an Automation Controller using a Continuous Deployment approach.

This catalog item provides code to demonstrate how to use Configuration as Code (CasC), using a Continuous Deployment approach, to maintain all the configurations of Ansible Automation Platform. The provided code is a starting point, and the asset guides you through how to utilize the code and make it your own.

=== This Asset Covers

* Configuring the Automation Controller using Configuration as Code
* Configuring GitOps basic elements (Webhooks)
* Promoting the Automation Controller Configuration from one environment to another (i.e., from dev to prod)

=== Prerequisites

* Some knowledge of Git would be beneficial
* Some knowledge of Ansible would be beneficial
* Having a GitHub account is necessary (https://github.com/join[Sign up for GitHub^])

=== Specifications

* One automation controller on Red Hat Enterprise Linux 8

=== Supporting Materials

==== Access Guide

After you complete provisioning, you receive an email with a website containing a user credential and access to the following:

* Automation controller web UI
* Visual Studio Code (including a terminal)
* Backup direct SSH access

The website provided with this information is dynamically created upon provisioning. The web address is your four-digit unique identification number plus the GPTE DNS "open.redhat.com"--for example: http://87f8.open.redhat.com/
