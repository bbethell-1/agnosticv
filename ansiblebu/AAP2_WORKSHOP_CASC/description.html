Welcome to the Workshop/Demo to configure an Automation Controller using a Continuous Deployment approach.

This catalog item provides code to demonstrate how to use Configuration as Code (CasC), using a Continuous Deployment approach, to maintain all the configurations of Ansible Automation Platform.

The provided code is a starting point, and the asset guides you through how to utilize the code and make it your own. This asset covers the following points:

  • Configuring the Automation Controller using Configuration as Code.
  • Configuring Gitops basic elements (Webhooks).
  • Promoting the Automation Controller Configuration from one environment to another (ie. from dev to pro)
These principles help prevent drift in configuration, allow changes to require approval before implementation, and help maintain both a development and production deployment.

Specifications

  • Two Automation Controller runnig on Red Hat Enterprise Linux 8

Supporting Materials

Access guide: After provisioning has completed, you'll receive an email with a website containing a user credential and access to the following:

  • Automation controller web UI (dev)
  • Automation controller web UI (pro)
  • Backup direct SSH access

The website provided with this information is dynamically created upon provisioning. The web address is your four-digit unique identification number plus the GPTE DNS "open.redhat.com" or something similar--for example: http://87f8.open.redhat.com/
