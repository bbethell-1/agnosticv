Red Hat OpenShift AI provides the Models-as-a-Service (MaaS) layer in this workshop, where one centrally hosted NVIDIA Nemotron model serves a whole organization. Learners use that single model from three perspectives: a developer using AI-assisted coding, an SRE using agentic infrastructure operations, and a platform stakeholder reviewing usage analytics. They create API keys, connect VS Code Chat in OpenShift Dev Spaces to the private model endpoint, and use MCP servers to query and troubleshoot a live OpenShift cluster. The workshop is aimed at platform engineers, developers, and SREs who want to learn how to consume and govern shared AI model infrastructure at scale.

== Detailed Overview

* *Introduction*
** Review the cost and operational problems of self-service GPU infrastructure and how a centralized MaaS layer addresses them
** Explore the MaaS components: API gateway, model lifecycle management, and observability
* *Configuring access to the MaaS-hosted model*
** Find the centrally managed model endpoint in the OpenShift AI Gen AI Studio
** Create an API key bound to a subscription policy and save the endpoint URL and key for later modules
* *AI-Assisted Development*
** Launch a pre-configured OpenShift Dev Spaces workspace
** Point VS Code Chat at the private MaaS endpoint through the Chat Completions API and validate it with a test prompt
* *Game Time*
** Generate a working application from a starter file using VS Code Chat in agent mode
** Test and debug the generated code in the Dev Spaces terminal
** Extend the application with ask mode and context-aware inline chat
* *System Administration with Agentic AI*
** Configure the Gen AI Studio Playground with Kubernetes and Rocket.Chat MCP servers and enable only the tools the smaller model needs
** Query live pods, namespaces, and vLLM logs with natural language prompts
** Diagnose a failing deployment and post the findings to a Rocket.Chat channel
* *Usage Analytics and Reporting*
** Explore the OpenShift AI Usage and Cluster dashboards
** Filter token consumption, request counts, and rate limiting by user, subscription, model, and time period
** Connect the metrics to capacity planning, cost attribution, and ROI
