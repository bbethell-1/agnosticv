Configure and validate a multi-site disaster recovery solution using InfoScale for Kubernetes 9.1.2 and OpenShift Virtualization 4.21.

== Audience

This workshop is designed for Platform Engineers, Storage Administrators, SREs, and OpenShift Virtualization Architects with intermediate experience who need to implement enterprise-grade disaster recovery for healthcare workloads.

*Experience level*: Intermediate

== Activities

* Verify and validate InfoScale for Kubernetes across multiple OpenShift clusters
* Install and configure the InfoScale DR Manager on both clusters
* Deploy a healthcare VM application on OpenShift Virtualization
* Configure asynchronous data replication using InfoScale custom resources
* Create and manage a DisasterRecoveryPlan using Kubernetes-native tooling
* Execute and validate a complete workload failover between clusters

== Environment

This workshop uses two pre-configured OpenShift 4.21 SNO clusters representing a primary production site and a geographically separate disaster recovery site.

You will have access to:

* Two pre-configured OpenShift SNO clusters: cluster-prod (Primary) and cluster-dr (Secondary)
* Access to both clusters via SSH through a bastion host
* All lab YAML files pre-loaded and ready to apply
* The OpenMRS Healthcare VM pre-deployed and running on cluster-prod

== Configuration

Two Single Node OpenShifts
* On the same Layer 2 network
* No ODF, no remote storage.  Just local disk that Infoscale uses.
* Two nodes of RAM: 48Gi CPU: 18
* Version pinned at OpenShift 4.21.3 for Infoscale operator compatibility.
