ifdef::field_content_service[]
== Field content runner

Your collection is started on the bastion. The platform does not wait for the playbook to finish.

[cols="1,3"]
|===
| systemd unit | `{field_content_service}`
| Inventory    | `{field_content_inventory}`
| Git repo     | {field_content_git_repo}
| Playbook     | `{field_content_playbook}`
|===

Follow the run with `sudo journalctl -u {field_content_service} -f` or `sudo podman logs -f field-content`.

If the playbook fails, push your fix then restart the service — it re-clones the repo and reruns from scratch:

....
sudo systemctl restart field-content
....

== Inventory groups

`bastions` — control node. `nodes` — the VMs listed above. SSH between hosts is preconfigured; from the bastion: `ssh <name>`.

Example targeting:

....
- hosts: nodes                         # every workload node, not the bastion
- hosts: "{{ groups['nodes'][0] }}"    # first node (always present)
- hosts: "{{ groups['nodes'][1] if groups['nodes'] | length > 1 else [] }}"
                                       # second node; skipped when the order has only one
....
endif::[]
