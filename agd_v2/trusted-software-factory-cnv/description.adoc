= Trusted Software Factory

== Overview

The Trusted Software Factory provides a minimal, production-ready environment for building secure software supply chains on OpenShift. This catalog item deploys the essential core components needed for artifact storage, source control, container registry, and authentication.

This is a streamlined implementation focused on four Trusted Software Supply Chain (TSSC) components, suitable for development, testing, and demonstration purposes.

== Featured Technology and Products

* *Red Hat Build of Keycloak (RHBK)* - Identity and access management with OpenShift OAuth integration
* *S4 (Sigstore Storage)* - S3-compatible object storage for artifacts and container images
* *Red Hat Quay* - Container image registry with S4 backend storage
* *GitLab CE* - Source code management and CI/CD integration

== Components Deployed

=== Authentication & Identity
* Keycloak operator and instance for SSO
* OAuth integration with OpenShift
* User management and realm configuration (tssc-keycloak namespace)
* Removes kubeadmin user after deployment

=== Object Storage (S4)
* S3-compatible object storage service
* Bucket for Quay registry backend
* Authentication enabled with access keys
* Route exposed for external access

=== Container Registry (Quay)
* Red Hat Quay operator
* Registry instance configured with S4 storage backend
* Integration with Keycloak for authentication
* Admin user provisioned

=== Source Control (GitLab)
* GitLab CE deployment via ArgoCD
* PostgreSQL database backend
* User and group provisioning
* Root user configured
* HTTPS enabled with dynamic certificates

== Technical Details

=== Deployed Workloads
1. `agnosticd.core_workloads.ocp4_workload_authentication` - Unified authentication with Keycloak
2. `agnosticd.core_workloads.ocp4_workload_s4` - S3-compatible object storage
3. `agnosticd.core_workloads.ocp4_workload_quay_operator` - Container registry with S4 backend
4. `rhpds.ads.ocp4_workload_gitops_gitlab` - GitLab source control via GitOps

=== Namespaces Created
* `tssc-keycloak` - Keycloak authentication
* `s4` - S4 object storage
* `quay-registry` - Quay container registry
* `gitlab` - GitLab source control

== Use Cases

* Demonstrate core Trusted Software Supply Chain components
* Development and testing environment for TSF/TSSC workflows
* Foundation for building more complex secure supply chain environments
* Learning platform for S4, Quay, GitLab, and Keycloak integration

== Architecture

This catalog uses a component-based architecture, provisioning an OpenShift cluster via the CNV pools component, then deploying the four core TSSC workloads on top of it.
