Getting Started with OpenShift is a hands-on lab series for developers, platform engineers, and DevOps engineers who are new to OpenShift. Students work on a live cluster through four self-contained labs, each building on the last — deploying a real containerized application, making it resilient, and eventually managing it with GitOps. The labs use DataSphere, a purpose-built demo app that visualizes a global datacenter network, as a consistent target throughout the series.

== Lab Guide

You can find a preview version of the link:https://rhpds.github.io/zt-ocp4-getting-started[lab guide^] here.

== Featured Technology and Products

* Red Hat OpenShift Container Platform
* Red Hat OpenShift GitOps (ArgoCD)
* OpenShift Source-to-Image (S2I)
* Helm

== Detailed Overview

* *Module 1: Your First Application*
** Deploy a containerized application and learn the core building blocks: Pods, Services, and Routes
** Explore how labels connect resources and how Services load-balance across pods
** Build the application yourself using `oc new-app` and observe a rolling update

* *Module 2: Expanding and Automating Your Application Deployment*
** Deploy a two-tier application (React UI + Python FastAPI) three different ways
** Build the API backend from source using OpenShift Source-to-Image (S2I)
** Deploy the full stack in one step using a Helm chart from the developer catalog

* *Module 3: Apps That Never Go Down*
** Configure liveness and readiness health probes and watch OpenShift restart a broken pod
** Scale to multiple replicas and observe zero-downtime pod replacement
** Set up Horizontal Pod Autoscaling and drive load to trigger automatic scale-out

* *Module 4: Git Is Your Source of Truth*
** Register a running application under GitOps management using a personal ArgoCD instance
** Edit a Helm values file in Git to provision a new datacenter hub and watch ArgoCD sync the change
** Explore drift detection, sync history, and rollback
