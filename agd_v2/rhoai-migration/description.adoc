Red Hat OpenShift AI migration lab takes a production-shaped RHOAI 2.25 cluster — with live model-serving workloads, workbenches, and data science pipelines — through an in-place migration to RHOAI 3.3. The environment carries ISVCs running on Serverless mode, a ModelMesh model, and workbenches built for the 2.x authentication model — all of which must be migrated in the correct sequence before the upgrade, or they stop serving. Learners use the `rhai-cli` assessment tool, perform hands-on workload conversions, drive the OLM-managed upgrade, and verify every workload end to end using a before-and-after diff against a captured baseline.

== Detailed Overview

* *Module 1: Test the Baseline Workloads*
** Exercise every user-facing workload: model inference endpoints, workbenches, pipelines, and Ray jobs
** Save responses to disk as a baseline archive for post-migration diff

* *Module 2: Assess the Cluster*
** Run `rhai-cli lint` and interpret critical findings versus warnings
** Learn why a clean assessment is not a complete workload inventory

* *Module 3: Convert the Model-Serving Workloads*
** Convert Serverless InferenceServices to RawDeployment using the `serverless-to-raw.sh` helper
** Migrate the ModelMesh model to a single-model KServe RawDeployment ISVC before removal

* *Module 4: Remediate the Platform*
** Disable removed components (Serverless, ModelMesh, Kueue, CodeFlare) in the correct order
** Tear down the Service Mesh v2 dependency and uninstall 2.x operators

* *Module 5: Handle the Workbench Images*
** Discover custom workbench images and triage them for the kube-rbac-proxy auth model
** Stop all workbenches before the upgrade

* *Module 6: Perform the Upgrade*
** Switch to the migration channel and drive the OLM-managed upgrade to RHOAI 3.3
** Move to the stable channel after the upgrade completes

* *Module 7: Post-Upgrade Verification*
** Confirm platform health, all four converted models serving via Gateway API, and workbench patching
** Verify HardwareProfile schema migration and AI Pipelines health

* *Module 8: Re-Test the Migrated Workloads*
** Re-run every test from Module 1 against the migrated endpoints
** Diff against the Module 1 baseline to prove nothing broke
