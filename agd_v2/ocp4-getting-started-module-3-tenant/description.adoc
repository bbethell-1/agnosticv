Lab 3 of the Getting Started with OpenShift series. Students learn to deploy and manage applications using GitOps principles with ArgoCD. They deploy the DataSphere application themselves by pointing ArgoCD at a Git repository, then make configuration changes through Git and watch ArgoCD automatically sync them to the cluster.

**Note**: This lab does not require completing Labs 1 or 2. Students can start here directly.

== What Gets Deployed

* *Student Account* — Keycloak SSO user with access to dedicated namespace
* *Gitea Repositories* — DataSphere source code and GitOps Helm chart repository
* *Student ArgoCD Instance* — Personal ArgoCD with OpenShift OAuth integration
* *GitOps Namespace* — `{user}-gitops` for ArgoCD and student workloads
* *Showroom Lab Guide* — Interactive tutorial with embedded terminal, console, and ArgoCD access

Students deploy DataSphere themselves using ArgoCD during the lab exercises.

== Lab Exercises

*Section 1: Your ArgoCD Instance*

* Log in to your personal ArgoCD instance
* Explore the ArgoCD UI and understand its components
* Learn about Projects, Applications, and GitOps workflows

*Section 2: Deploy DataSphere Under GitOps Management*

* Create an ArgoCD Application resource
* Point ArgoCD at the DataSphere Helm chart in your Gitea repository
* Watch ArgoCD automatically sync and deploy the application
* Verify the deployment in the OpenShift Console

*Section 3: Make Configuration Changes Through Git*

* Edit Helm values in the datasphere-gitops repository
* Add a new datacenter location to the DataSphere map
* Commit and push changes to Gitea
* Watch ArgoCD detect the change and sync automatically

*Section 4: Understand Drift Detection and Self-Healing*

* Make a manual change in OpenShift (bypassing Git)
* Observe ArgoCD drift detection
* Watch Self-Heal restore the desired state from Git
* Understand why Git is the source of truth

== Pre-requisites

None. This lab can be taken independently of Labs 1 and 2.
