== Red Hat One: Platform Engineering Workshop

The Platform Engineering Workshop is a multi-module workshop that serves as a practical, learn-by-example, hands-on experience for Platform Engineers.

The workshop guides a Platform Engineer through a journey map of understanding why a platform is critical for increased developer productivity, and how to set one up — from the Design phase to a more mature Product-as-a-Platform phase.

=== Learning Objectives

* Understand the need to implement Platform Engineering disciplines in their organization and see the benefits of improving Developer Productivity.
* Learn how to design a Thinnest Viable Platform (TVP) based on the needs of development teams and ensure they are highly productive.
* Constantly assess the investment into your own Internal Developer Platform (IDP), understand how it can be enhanced, and convince development teams to start adopting it.
* See Red Hat as a partner in their Platform Engineering journey through Red Hat's products, Professional Services, and Partner Ecosystem.

=== Modules Overview

* Module 1: Discovery
// Innovation Labs style session
// Discuss the challenges currently faced by developers and the need for an Internal Developer Platform. Learn why a developer platform is necessary for rapid innovation.

* Module 2: Design the Internal Developer Platform
// Architect an IDP, install, and bootstrap it to create an MVP.
// Platform as a Product, Feedback Cycle with users.

* Module 3: Test Drive Red Hat Developer Hub
// Beta-User takes the IDP for a test drive with a simple software template.
// Get familiar with the organization's environment with features of RHDH and Plug-Ins.

* Module 4: Discovery
// Platform Engineers configure Software Templates and Integrations to import existing software components from Git.
// Developers use Software Templates to import their existing software components and create isolated development environments for feature development.
// Developers can view the progress in a single-pane of glass from Developer Hub.

* Module 5: Setup Build, Test, & Deploy Outer-loop
// Developer issues a merge request from the feature branch which is accepted only post peer-review.
// Pipelines provided by the platform engineers support promotion to production. Post-merge, the pipeline updates manifests in Dev and Stage environments; Deployment to Prod is only based on appropriate approvals.

* Module 6: Establish Security and Compliance _(Coming soon)_
// Platform Engineers introduce Red Hat Trusted Artifact Signer as part of the pipelines to ensure safety rails are in place and only signed artifacts are allowed to Production.

* Module 7: Enable Continuous Platform Improvements _(Coming soon)_
// Feedback loop for continuous platform improvements leading to better developer productivity.
// Enable developer self-service, feedback, and help Platform Engineers gain insights and analytics.

*Provisioning Time*: ~120 min
