This workshop explores the integration of security into development and deployment practices using Red Hat OpenShift and various Red Hat security tools. It emphasizes the importance of 'shifting left'—embedding security early in the development lifecycle—and offers hands-on activities to transition from non-secure to secure development pipelines.

== Introduction to the Workshop

Welcome to a compelling session where theoretical discussion meets practical application in securing development and deployment practices. This workshop leverages the Red Hat Developer Hub (RHDH) to enhance the developer experience by providing a centralized platform with resources, documentation, and tools.

Participants will transform a non-secure development pipeline into a secure one, emphasizing the practical benefits of integrating security tools such as The Update Framework + Fulcio + Sigstore (TAS), Red Hat Advanced Cluster Security (ACS), and SonarQube into their Red Hat OpenShift workflows.

Throughout this journey, participants will assume the roles of developers, quality assurance engineers, and security engineers, confronting challenges these personas typically face. The workshop unfolds over three engaging chapters:

=== Chapter 1: A Day in the Life of a New Developer

Participants begin as new developers eager to write code. This chapter highlights the value of Internal Developer Portals (IDPs), like the Red Hat Developer Hub (RHDH), in streamlining developer onboarding, making it efficient and pleasant. RHDH reduces cognitive overload, allowing developers to concentrate on what they do best—crafting quality code.

=== Chapter 2: Tightrope Walking without a Net

As the story progresses, participants become Quality Assurance Engineers, learning about the risks of equipping developers with powerful tools without necessary security measures, which could expose the organization to threats.

=== Chapter 3: Red Hat Trusted Application Pipeline to the Rescue

In the final chapter, participants act as Red Hat Consultants demonstrating the capabilities of the Red Hat Trusted Application Pipeline (RHTAP), illustrating how it meets security challenges without hindering developer productivity.

== Workshop Challenge Overview

Participants face the challenge of learning and implementing the transition from non-secure development practices to a secure development pipeline. This transformation is vital for understanding how to effectively mitigate vulnerabilities and integrate thorough security measures throughout the software development lifecycle.
