= AgnosticV Promotion Automation
:toc:
:toc-placement!:
:source-highlighter: highlight.js

Tooling for promoting AgnosticV catalog items to production and event stages.

toc::[]

== Overview

Promoting a catalog item to `prod` or `event` involves several coordinated steps:

1. Parse `common.yaml` to discover which repos use `{{ tag }}`
2. Check GitHub for the highest existing tag across all repos
3. Create the new tag on every discovered repo _and_ the deployer
4. Update the stage YAML files (`tag:`, `__meta__.deployer.scm_ref:`, and optionally `cloud_provider_version:`)
5. Optionally update pinned collection versions in `common.yaml` when newer releases are available

The `agd-promote.py` script automates all of the above. A companion GitHub Actions workflow (`validate-tags.yml`) runs on PRs to verify that the tags referenced in changed stage files actually exist on all repos.

== Prerequisites

* **Python 3.12+** (used to create the virtual environment automatically)
* **GitHub CLI** (`gh`) — authenticated with access to the `agnosticd`, `rhpds`, and related orgs
* Write access to the repos that need tagging

Verify your setup:

[source,bash]
----
gh auth status
python3 --version
----

== Installation

=== The CLI script

The tool consists of two files in the `scripts/` directory:

[cols="1,3"]
|===
| File | Purpose

| `agd-promote`
| Shell wrapper — creates a virtual environment in `/tmp/agd-promote-venv` on first run, installs dependencies, and delegates to the Python script. **This is the entry point you should use.**

| `agd-promote.py`
| Python implementation — should not be called directly (use the wrapper instead).
|===

No manual installation of Python packages is needed. The wrapper handles everything:

[source,bash]
----
# First run creates the venv automatically
./scripts/agd-promote --help

# Subsequent runs reuse the existing venv
./scripts/agd-promote agd_v2/mcp-with-openshift patch --dry-run
----

To force a fresh virtual environment (e.g., after a Python upgrade), delete and re-run:

[source,bash]
----
rm -rf /tmp/agd-promote-venv
./scripts/agd-promote --help
----

=== The GitHub Actions workflow

The workflow file is `.github/workflows/validate-tags.yml`. It is activated automatically on pull requests to `master` that modify any `agd_v2/*/prod.yaml` or `agd_v2/*/event.yaml` file.

It uses the existing `RHPDS_BOT_REPO` repository secret for cross-org GitHub API access. No additional secrets or configuration are required.

== Usage

=== Basic promotion (patch bump)

[source,bash]
----
./scripts/agd-promote agd_v2/mcp-with-openshift patch
----

This will:

1. Discover all repos from `agd_v2/mcp-with-openshift/common.yaml`
2. Query GitHub for the highest existing tag matching the prefix (e.g., `mcp-openshift-`)
3. Compute the new version (e.g., `1.0.2` -> `1.0.3`)
4. Display a plan and prompt for confirmation
5. Create tags on all repos
6. Update `prod.yaml` and `event.yaml`

=== Dry run (preview only)

[source,bash]
----
./scripts/agd-promote agd_v2/mcp-with-openshift patch --dry-run
----

Prints the full promotion plan without making any changes or prompting for confirmation.

Example output:

[source]
----

=== Minor or major bump

[source,bash]
----
./scripts/agd-promote agd_v2/mcp-with-openshift minor
./scripts/agd-promote agd_v2/mcp-with-openshift major
----

=== Update only specific stages

[source,bash]
----
# Only update prod.yaml (skip event.yaml)
./scripts/agd-promote agd_v2/mcp-with-openshift patch --stage prod

# Only update event.yaml
./scripts/agd-promote agd_v2/mcp-with-openshift patch --stage event
----

=== Catalog items with cloud_provider_version

For items like `ocp-cluster-cnv-pools` that have a separate `cloud_provider_version`, the tool handles it automatically:

[source,bash]
----
./scripts/agd-promote agd_v2/ocp-cluster-cnv-pools patch
----

To bump the cloud provider version independently from the main version:

[source,bash]
----
# Main version: patch bump (1.2.3 -> 1.2.4)
# Cloud provider version: minor bump (1.2.3 -> 1.3.0)
./scripts/agd-promote agd_v2/ocp-cluster-cnv-pools patch --cloud-provider-bump minor
----

=== Skip tagging (YAML-only update)

If tags were already created manually or by a previous partial run:

[source,bash]
----
./scripts/agd-promote agd_v2/mcp-with-openshift patch --skip-tagging
----

=== Override tag prefix

If the auto-detected prefix is wrong or the stage file doesn't exist yet:

[source,bash]
----
./scripts/agd-promote agd_v2/my-new-item patch --tag-prefix my-item
----

=== Secret Documentation

Every vault-encrypted variable in `includes/secrets/` must have a `# @field: value` comment block immediately above it.
CI enforces this for any secret file modified in a PR.

Required fields:

* `@owner` — Person(s) responsible (`Name <email>`, comma-separated for multiple)
* `@purpose` — What this credential does
* `@impact` — `HIGH`, `MEDIUM`, or `LOW` followed by explanation
* `@expiration` — `YYYY-MM-DD` or `never`
* `@rotation` — How to rotate or renew
* `@source` — Where the credential was created (URL or description)
* `@exposure` — Where the decrypted value ends up at runtime

Any field can be set to `UNKNOWN` if you don't know the answer.

See `includes/secrets/TEMPLATE.yaml` for a complete example.

=== Validate tags in a PR (CI mode)

Used by the GitHub Actions workflow, but can also be run locally:

[source,bash]
----
./scripts/agd-promote --validate-pr agd_v2/mcp-with-openshift/prod.yaml
----

Checks that the tag specified in `prod.yaml` exists on every repo discovered from `common.yaml`. Exits with code 0 if all tags are present, 1 if any are missing.

Multiple files can be validated at once:

[source,bash]
----
./scripts/agd-promote --validate-pr \
  agd_v2/mcp-with-openshift/prod.yaml \
  agd_v2/ocp-cluster-cnv-pools/event.yaml
----

== How It Works

=== Repo discovery

The tool reads `common.yaml` and classifies repos into three categories:

[cols="1,3,2"]
|===
| Category | Description | Example

| **A: Tagged**
| Collections where `version: "{{ tag }}"` plus the deployer repo. All receive the new tag.
| `agnosticd/core_workloads`, `agnosticd/agnosticd-v2`

| **B: Pinned**
| Known collections with hardcoded versions (showroom, assisted_installer). The tool checks GitHub for newer releases and updates `common.yaml` if available.
| `agnosticd/showroom` at `v1.3.9`

| **C: Cloud provider**
| When `cloud_provider_version: "{{ tag }}"` and `cloud_provider != "none"`. Gets tagged with a bare version number.
| `agnosticd/cloud_provider_openshift_cnv` at `1.2.3`
|===

=== Version resolution

The tool queries _all_ tagged repos for the highest existing tag matching the prefix. This handles cases where repos are out of sync — it always bumps from the global maximum.

=== YAML editing

Files are edited line-by-line (not via `yaml.dump`) to preserve comments, formatting, and the `#include` directives that are specific to AgnosticV.

=== Error handling

[cols="1,2"]
|===
| Scenario | Behavior

| `gh auth` fails
| Exits with authentication guidance

| Repo inaccessible
| Lists all inaccessible repos, exits before any mutations

| Tag already exists
| Skips that repo, continues with the rest

| Tag creation fails midway
| Reports status, prints cleanup commands, does _not_ update YAML files

| Unexpected YAML format
| Errors with details, does not write the file

| Stage file missing
| Skips with a warning (e.g., `event.yaml` may not exist for all items)
|===

== Typical Workflow

[source,bash]
----
# 1. Preview the promotion
./scripts/agd-promote agd_v2/mcp-with-openshift patch --dry-run

# 2. Run the promotion (creates tags + updates YAML)
./scripts/agd-promote agd_v2/mcp-with-openshift patch

# 3. Review the local changes
git diff

# 4. Commit and open a PR
git add agd_v2/mcp-with-openshift/
git commit -m "Promote mcp-with-openshift to 1.0.3"
git push origin HEAD
gh pr create --title "Promote mcp-with-openshift to 1.0.3"
----

The `validate-tags` workflow will automatically verify that all tags exist when the PR is opened.

== CLI Reference

[source]
----
usage: agd-promote.py [-h] [--validate-pr FILE [FILE ...]] [--stage STAGE]
                      [--cloud-provider-bump {patch,minor,major}]
                      [--dry-run] [--skip-tagging] [--tag-prefix TAG_PREFIX]
                      [item_path] [{patch,minor,major}]

positional arguments:
  item_path             Path to catalog item dir (e.g., agd_v2/mcp-with-openshift)
  bump                  Version bump: patch | minor | major

options:
  --validate-pr FILE    CI mode: validate tags in given stage files exist
  --stage STAGE         Comma-separated stages to update (default: prod,event)
  --cloud-provider-bump Separate bump for cloud_provider_version (default: same as main)
  --dry-run             Show plan only, no confirmation prompt
  --skip-tagging        Only update YAML files, skip git tag creation
  --tag-prefix          Override auto-detected tag prefix
----
