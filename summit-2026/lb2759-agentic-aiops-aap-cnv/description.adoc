Ansible Automation Platform combines with Red Hat AI and Ansible Lightspeed to create intelligent, self-healing infrastructure that can detect, analyze, and remediate failures automatically. This hands-on lab demonstrates AIOps principles across three domains: service remediation, network automation, and Windows event-driven automation. Learners build Event-Driven Ansible workflows that use AI to generate remediation playbooks without writing any Ansible code manually.

== Detailed Overview

=== Part 1: AIOps with Apache Remediation

* *Log Enrichment and Prompt Generation Workflow*
** Build an EDA-triggered workflow responding to Apache service failures
** Use Red Hat AI to analyze error logs and generate root cause analysis
** Send incident details to Mattermost for notification
** Create job templates with AI-generated prompts for Ansible Lightspeed

* *Remediation Workflow*
** Use Ansible Lightspeed to generate remediation playbooks from AI prompts
** Commit generated playbooks to Gitea source control
** Review AI-generated playbook content before execution
** Execute remediation to fix the broken Apache service

=== Part 2: Network Automation with Splunk

* *Splunk for Network Observability*
** Configure Splunk data inputs to receive Cisco syslog messages
** Run router setup playbook establishing OSPF routing
** Create Splunk alerts for OSPF neighbor state changes
** Configure webhook integration with Event-Driven Ansible

* *Event-Driven Ansible*
** Verify EDA rulebook activation for OSPF events
** Understand the observe-evaluate-respond automation loop
** Review rulebook webhook listener configuration

* *Network Workflow - Three OSPF Scenarios*
** Scenario 1: OSPF neighbor down due to interface shutdown
** Scenario 2: OSPF neighbor down due to incorrect network type
** Scenario 3: OSPF neighbor down due to hello timer mismatch
** Human-in-the-loop approval with check mode validation before applying fixes

=== Part 3: Windows Events and AI-Driven Ticketing

* *AD Account Creation Event*
** Winlogbeat captures Windows Security events and forwards them to Kafka
** EDA rulebook detects AD account enablement (Event ID 4722) on the `windows-events` topic
** Automatically creates a Mattermost ticket with event payload details (username, domain, SID)

* *Firewall Event with AI Enrichment*
** EDA detects Windows Firewall rule changes (Event ID 2004) matching specific rule names
** Red Hat AI (Granite LLM) analyzes the raw event and generates actionable security intelligence
** Creates an AI-enriched Mattermost ticket with both raw event data and AI analysis
