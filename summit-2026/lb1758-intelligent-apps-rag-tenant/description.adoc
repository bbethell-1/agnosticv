Red Hat OpenShift AI is used to build an enterprise Retrieval-Augmented Generation (RAG) system that answers IT support questions from private incident data. Learners deploy a mock ServiceNow API, a Milvus vector database, and a Kubeflow data science pipeline, then query the system with a Granite LLM through LangChain. A second track extends the pipeline with event-driven PDF ingestion using Knative Eventing and Apache Kafka. The lab suits platform engineers, data scientists, and AI/ML engineers and runs about two hours.

== Detailed Overview

* *The Parasol Company Scenario*
** Understand why knowledge gets trapped in IT service management systems
** Review how RAG augments an LLM with private data and the components of an enterprise RAG architecture

* *Lab Overview and Setup*
** Navigate the OpenShift AI dashboard and the OpenShift console
** Query a Granite LLM through an OpenAI-compatible API from a Jupyter notebook
** Build prompts with LangChain templates

* *Deploying the Mock ServiceNow API*
** Deploy the application declaratively with an Argo CD Application
** Validate the running service with `oc exec` and `curl`

* *Deploying the Milvus Vector Database*
** Deploy Milvus and its dependencies through GitOps
** Understand the role of a vector database in a RAG architecture

* *Importing, Configuring, and Monitoring the Data Science Pipeline*
** Import a compiled Kubeflow pipeline into OpenShift AI
** Set runtime parameters that connect the pipeline to the data source and vector store
** Monitor the run and inspect component logs

* *Querying the RAG System*
** Run the two-step RAG process: similarity search in Milvus, then generation
** Build a LangChain RetrievalQA chain and interpret responses grounded in private data

* *Event-Driven PDF Ingestion*
** Trace a CloudEvent from an S3 upload through Kafka to a pipeline run
** Explore the Knative Broker, Trigger, and KafkaSource that automate ingestion
