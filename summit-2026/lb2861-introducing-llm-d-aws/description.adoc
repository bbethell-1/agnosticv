llm-d is a distributed inference orchestration layer that dramatically reduces tail latency (P95/P99) through intelligent cache-aware routing. This hands-on workshop addresses a critical production challenge: adding more GPUs improves capacity but doesn't fix tail latency for your most frustrated users. Through the ParasolCloud scenario, learners deploy Llama 3.1 8B, benchmark single-GPU baseline performance, scale to 4 GPUs with naive load balancing, then deploy llm-d with Precise Prefix Cache Aware Routing to prove that intelligent routing delivers what naive scaling cannot.

== Detailed Overview

[NOTE]
====
This workshop assumes experience with vLLM, Kubernetes/OpenShift, KServe, and Grafana. We will **not** cover transformer fundamentals, vLLM internals, or Kubernetes basics.
====

* *Deploy Model & Core Concepts*
** Deploy Llama 3.1 8B Instruct using KServe and vLLM on a single GPU
** Understand three bottlenecks causing high tail latency: prefill queuing, KV cache misses, unpredictable queuing
** Learn how llm-d's cache-aware routing maximizes cache hits and reduces P95/P99

* *Benchmark & Establish Baseline*
** Configure Grafana dashboard to monitor vLLM metrics in real-time
** Run GuideLLM benchmarks to measure TTFT, ITL, and throughput
** Execute custom multi-turn benchmarks simulating ParasolCloud's realistic workload

* *Scale vLLM & Compare Performance*
** Deploy vLLM with 4 replicas using naive random load balancing
** Run benchmarks to measure P95/P99 latency with more GPUs
** Discover critical insight: more GPUs increase capacity but don't fix tail latency

* *Deploy llm-d & Benchmark*
** Deploy llm-d with LLMInferenceService and Precise Prefix Cache Aware Routing
** Configure llm-d to orchestrate 4 vLLM backend instances intelligently
** Measure P95/P99 improvements and observe 90%+ cache hit rates
